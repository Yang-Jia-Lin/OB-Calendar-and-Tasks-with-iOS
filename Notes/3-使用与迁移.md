# 使用与迁移

更新：2026-11-07。桌面 0.1.0 为首版预览，OB 0.7.0 增加连接及交接模式；实际运行实例没有自动重新加载，真实业务没有自动切换。目标范围见[产品需求](1-产品需求.md)。

## 1. 现在继续怎么用

当前 Windows 仍通过完整 OB 插件计时和同步。Components 卡片按钮、插件页、命令和状态栏操作同一会话；卡片再次点击默认结束并只记工时，明确选择“结束并完成”才完成原任务。

0.6.1 已发布并在本机安装过，本轮没有重载或核实当前宿主加载版本。该版本打开计时面板时等待布局恢复，复用已有标签；没有时放入右侧原标签组。默认启动后关闭“反向链接”和“全部属性”，保留当前笔记属性；设置可关闭启动清理。此行为依赖现有插件运行。

云端仍使用原有账户、日历和提醒事项列表。不要为文档调整重新迁移现有课题、清空待同步队列或重新创建同名任务。未完成的 Markdown 迁移继续按明确选择处理，已有真实关联与历史保留。

完整操作手册保存在[旧版三页使用说明](Archive/2026-11-07-OB完整工作台/4-三页使用说明-旧版.md)，其中的旧桌面／跨端规划不再是当前目标。

## 2. Windows 桌面首版预览的使用流程

已有 OB 数据的用户先完全退出桌面，再加载 OB 0.7.0 完整模式，结束计时并等待当前请求结束，执行“准备交接到 Windows 桌面版”。核对提示后冻结旧写入者，生成受保护的交接目录并释放本机宿主互斥；再打开桌面，在设置中预览并导入目录，保留原任务、绑定、工时、日历身份和未确认请求。重新加载 OB 为连接模式，再补充失效的授权。不要在导入前新建同名任务；已有本地操作或不匹配连接时导入会拒绝。相同账户的只读缓存和单纯退出／配置记录不妨碍导入。

纯新用户先在设置中明确确认旧写入者已经停止，启用独立模式，再连接提醒事项和 CalDAV 日历，配置默认工时日历及列表映射。未交接／确认前，桌面不启动第二套计时、不提交业务操作。OB 0.7.0 完整模式与桌面共享本机 OS 宿主互斥；0.6.1 不识别新互斥，必须遵循上述升级／交接步骤。它不是跨设备锁。当前安装包随附 Node／Python／固定 SDK，正常启动不安装依赖；用户级安装，业务数据在 `%LOCALAPPDATA%/CalendarTaskTimer/Desktop`，凭据受 DPAPI 或私有目录 ACL 保护。

重新加载已升级的 OB 插件后，连接模式不再初始化 TimerController 或云端 Worker。课题按钮由本机桌面后台保存并启动，确认后显示时长；桌面、灵动岛和 OB 共用一份会话。关闭主窗口或 OB 不结束计时，睡眠／休眠继续计入；托盘明确退出时保存为暂停。

结束后的记录先在本机保存，再由后台同步 iCloud。断网可计时并保存；上传失败从桌面查看待提交状态和重试。App 未启动时按钮尝试唤起它，连接失败明确提示，不产生另一套活动会话。

待办、日程编辑、分类、补记和同步异常集中到桌面 App；OB 保留课题入口。完整插件的退出应在桌面接管及真实绑定验证通过后执行。

## 3. Mac 计时工具上线后的流程（待实现）

待办和日程继续用原生提醒事项、日历。打开轻量计时工具，填写活动名称并选择工时日历，即可开始、暂停、继续和结束。若在 Mac 的 OB 中使用课题按钮，它连接本机 Mac 计时工具。

开始后不与 Windows 同步进行中状态，也不要求 Windows 在线。结束时工时先保存在 Mac 本机，再写入已经配置好的 iCloud 日历，由系统同步已保存结果。

首次写日历需要相应系统授权；拒绝授权或目标不可写时，工时仍留在本机待处理。界面应区分“本机记录已保存”“已写入系统日历”和实际可确认的云端状态，不能把本地保存说成全部设备已经同步。重复点击重试只对应同一份记录。

Mac 首版不自动完成提醒事项；任务的勾选、重复规则和列表管理继续在原生 App 操作。

## 4. 安全切换清单

1. 先验证新 App 使用专用样例：独立计时、暂停／恢复、OB 断开、离线、崩溃和日历重复提交。
2. 结束旧插件的活动计时，核对并记录未确认操作。没有确认的远端提交先按原 ID 查证，不重新创建同名对象。
3. 备份原设置、绑定、会话、工时与队列；保留原始数据直到完成导入核对。
4. 受控导入到新宿主，保留稳定任务引用、记录 ID 和原提交身份。账户采用受保护迁移或重新授权。
5. 验证同一课题按钮与桌面指向同一任务、结束只产生一份工时、旧历史和未同步内容可追溯。
6. 切换为轻量连接，停止旧完整插件的计时与云同步。不要让两个宿主同时写会话或处理相同队列。

Windows 与 Mac 分别切换并验收，不通过复制插件程序文件宣称 Mac 兼容，不通过复制正在写入的日志实现活动计时接续。

## 5. 日记与现有笔记

已有日记时间轴是普通 Markdown，始终保留。轻量连接继续提供原更新按钮、命令以及 `updateDiaryFromNote`，原 Templater 自动入口不需要重写；快照改由桌面按日提供，OB 继续校验日期、备份、保护生成区外手写内容。真实笔记与自动触发仍需在实际交接后验收。

现有模板位置：`Others/Template/Daily Template.md`；时间轴排版：`Others/Template/日记时间轴模板.md`。日期使用 `日记日期` 或合法年月日文件名，不能拿当天日期替代历史日记。

`<!-- ctt-diary-timeline:start -->` 与 `<!-- ctt-diary-timeline:end -->` 之间是生成区；手写内容放在区外。当前更新前备份位于 `.obsidian/plugins/calendar-task-timer/diary-backups/`。详细现有规则见[归档的日记说明](Archive/2026-11-07-OB完整工作台/3-日记时间轴使用-旧版.md)。

归档只搬动工程文档，不处理真实笔记、日记模板、账户凭据、任务、会话或备份文件。

## 6. 桌面首版预览的验收与回退

桌面 0.1.0 先交付功能，OB 0.7.0 保留完整旧模式及受控交接入口，不自动切换真实账户，也不自动重新加载插件。离线示例使用独立目录；示例不能登录真实账户、导入业务数据或提交云端操作。正式使用前先从托盘退出示例，再运行安装后的应用。

安排日期首次启用前，在设置创建专用验证样例，到 Apple 原生提醒事项按说明补入标记，再回桌面“核对原生往返”；通过前不会修改真实任务的安排信息。日历面板在桌面内部显示；主窗口、面板与灵动岛可分别隐藏。灵动岛只负责当前计时，详细编辑回主窗口。未确认的旧本地任务完成意图保留，可核对原笔记后明确选择“仅保留工时”；不盲目重建旧任务。

正式切换前仍需手动验证：Win+D 后面板可见及点击、资源管理器重启恢复、多屏／DPI、真实睡眠／休眠、Apple 原生往返，以及实际课题按钮与日记自动更新。未完成的检查不以模拟或隔离样例替代。安装包当前未配置发布签名，不提供自动更新。

本机离线样例已由用户手动确认 Win+D 后日历和灵动岛可见、日历可以点击；主窗口及灵动岛的同一任务启动／暂停同步也已查看。其余平台场景和正式业务切换继续按上述清单核对。首次关闭主窗口占用超出目标，已实施隐藏 WebView 暂停与 Python 空闲退出，修正进程统计后仍需复测；不宣称 350MB 目标已经通过。

回退时先结束桌面计时、核对其待提交队列并完全退出桌面后台，备份桌面数据目录及交接导出。仅在确认唯一写入者已经停止后，使用导出的 `legacy-settings.json` 恢复旧插件设置，再加载相应程序备份。桌面接管后产生的新工时和新队列不能靠覆盖旧文件自动回灌；存在新业务时先核对，不删除新数据或重放旧请求。旧目录及导出快照保留以便追溯。

# 开发日志

截至 2026-11-01，软件版本为 **0.2.20**。本文件统一保存开发历史、版本变化、验证证据和验收基线，取代原 Verification、RemindersValidation、RemindersEvidence 三份文档。当前产品要求见 [1-产品需求](1-产品需求.md)，架构见 [2-架构设计](2-架构设计.md)，开发约定见 [0-开发约定](0-开发约定.md)。

## 更新约定

- 新日期放前面；同日的新事项放在该日最前，软件版本按数字倒序（0.2.11 在 0.2.10、0.2.9 前）。插件与探针曾并行开发，同日缺少精确时间的事项按版本／批次汇总，不推断两条工作线的先后。
- 每次有实质开发、版本发布、需求／架构变更或验证结果，都在下方“开发记录”之后插入最新条目；不再另建逐版本日志。纯文档工作不虚增软件版本。
- 写明变更、实际验证、证据／产物／提交及未完成项。区分“已实现”“仅设计”“模拟验证”“真实账户验证”“待测”。
- 测试数量是对应版本／批次的证据，不累计当成跨版本总成绩。未重跑就注明；本地测试和缓存不能代替云端往返。
- 原始失败及用户后续更正保留在同一历史条目，后续结果另加新条目，不倒改旧失败为从未发生。不得把密码、Cookie、令牌或真实对象 ID 写入日志。
- 日期统一按北京时间记录；没有可靠日期的早期事项标为回溯，不编造精确时间。当前实际文件与 manifest 优先于旧提交标题中的版本写法。

后续条目可沿用：

```markdown
## YYYY-MM-DD｜vX.Y.Z 或工作项｜标题

- 状态／范围：已实现、文档设计、模拟验证或真实实测。
- 变更：解决什么问题，关键行为是什么。
- 验证：执行了什么、结果与限制；未执行的检查明确写出。
- 证据／产物／提交：相关路径或提交；不含秘密。
- 待办／风险：哪些内容仍未完成。
```

## 2026-10-26｜v0.2.3｜远端已删除后的本地收尾

- 用户反馈：已在远端删除日程，本地卡片仍显示“待删除”，刷新也未消失。只读日志检查读到该请求的 CalDAV HTTP 404；没有修改日常库的日志或云端数据。
- 根因：本地删除队列会补画待删除占位卡片，刷新原先只重新读取 FCR 和待办，未核对／结束该队列。FCR 删除失败时又会把条目回滚到缓存，形成持续残留。
- 新增只读 reconcileDeletions：手动刷新后的异步回读及前台周期回读会检查可用 FCR 日历中是否还存在对应 UID，缺失则结束本地请求，移除相关本地分段，不再发送 DELETE。
- 点击待删除卡片可查看恢复操作。对于 HTTP 404／410，用户确认已在远端删除后，可显式清理本地残留；不会新建或删除云端事件，不改变其他分段／待办。普通网络失败不提供此清理入口，同 UID 内容变化时拒绝清理。
- 删除确认日志增加可选 resolution，区分 deleted、absent-in-fcr、user-confirmed-remote-deletion。已核对缺失或用户确认后的同 UID、同内容旧缓存不会重新补画，变更内容的事件仍保留可见。
- CalDAV 的 href／ETag 刷新与用户内容变化分别处理，避免同一事件仅因资源元数据刷新而无法继续删除。
- FCR 公开查询仍是缓存视图，不能据此宣称完成服务端条件读写；本轮复现与修复验证使用模拟 FCR，真实库更新后需本机试用。

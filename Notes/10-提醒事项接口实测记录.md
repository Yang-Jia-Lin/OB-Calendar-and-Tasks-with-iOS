## 用户操作和继续方式

**本轮操作已结束，不重跑新建。** 用户确认隐藏已完成项目造成初次显示误判；随后确认 iPad 改名时自行调整了分隔符格式。实际标题变化和完成状态已从服务器读回。用户最后确认四条电脑样例已从 iPad 消失、手工设备验证任务仍在。下列完整流程仅作原操作说明，不要求重新执行。

1. 在本机登录页输入 Apple 账户，按提示选择账户地区；输入 Apple 账户密码并完成验证码验证。不要将凭据发送到聊天。
2. 登录后，在 iPad **iCloud 提醒事项** 建立一份普通专用列表，名称以 `ICT-Verify-` 开头，手动建立标题为 `ICT-设备验证` 的普通任务；在页面输入该列表完整名称。
3. 探针只读确认到同一任务后，才创建四条专用样例。页面将提示核对日期和时刻、电脑完成／恢复，并让用户在 iPad 反向改名和完成。
4. 如果结果不一致或尚未核对，页面输入 `n` 或 `s` 停止；不会自动重复创建任务。不确定创建结果需要人工核对，不能按同标题自动删除。
5. 正常结束可选择仅清理本次探针创建的四条任务；手工设备验证任务与列表保留。网络失败或退出后保留私有清单供恢复，不重新开始一轮冒充重试。

独立终端及继续入口见 [探针说明](../Coding/Probes/IcloudReminders/README.md)。原登录页已经停止，继续页面使用 `--resume`，不另开一轮新建以冒充重试。

## 2026-10-29 · 第二轮受控异常与外部变化

执行 `reliability.py` 后，由用户在 iPad 原专用列表中完成一条改名和一条删除，再由 `reliability_finish.py` 核对和清理。本轮结果独立保存为 `reliability-status.json`，没有覆盖第一轮核心结果。

| 场景 | 结果与证据边界 |
| --- | --- |
| 断网读取 | 在发送前注入连接错误，SDK 明确失败，匹配请求只有 1 次；解除注入后真实重读成功。不是操作系统断网 |
| 离线写入／请求超时 | 在修改请求发送前分别注入连接错误和读取超时；失败后真实云端任务内容不变，没有误报成功或自动重试 |
| 修改已提交但响应丢失 | 请求实际得到服务器应答后注入超时；按同一 ID 重读确认已完成，没有再次提交修改 |
| 新建已提交但响应丢失 | 发送前从创建请求提取并持久化生成 UUID，随后真实提交、丢弃响应；按该 ID 找回同一任务，只有一次创建发送，没有重新创建 |
| 会话失效提示 | 将模拟 401 送入 CloudKit 客户端，得到认证错误并停止；解除模拟后真实会话仍可读。没有撤销密码或破坏 Cookie，不代表真实会话到期已通过 |
| 两个真实客户端并发 | 第二客户端修改专用任务后，探针守卫拒绝旧快照；另行尝试 SDK 旧版本写入得到 API 错误，外部优先级和完成状态保持。此场景通过，不扩张为所有并发竞态都已证明 |
| 第二客户端删除 | 实际云端删除后，探针拒绝旧快照编辑，任务保持删除，没有创建或复活 |
| iPad 原生外部变化 | 用户在 iPad 为指定标题追加 X，并删除另一条专用样例；电脑按原 ID 精确读回改名并识别删除。旧快照编辑均被拒绝 |
| 清理 | 四条本轮样例都已在服务端确认删除；两条由外部客户端／iPad 删除，另外两条由探针按原清单清理。原手工设备验证任务和列表保留。没有重复要求用户核对相同删除能力 |

最终状态为 `controlled_reliability_batch_complete`；19 个场景检查事件通过，0 个失败。高层写调用尝试数为 12，包含发送前注入失败及过期版本被拒绝的调用，**不等于 12 次成功云端变更**。原始对象 ID、会话与请求身份仅在私有清单中保存。

关键实现约束：候选高层 `create()` 不暴露调用者指定 ID。本轮依靠传输前持久化实际请求 UUID，才能在响应丢失后找回。后续正式 Provider 必须提供等效的持久化／核对机制；不能把本次结果理解为直接重试高层创建就是幂等。Probe 的守卫和日志也不等于 OB 产品已经具备离线队列。

已准备 `overnight_check.py`：北京时间 2026-10-30 起可复用会话只读观察所选列表，同日运行只标注“未到隔日观察日期”；不自动调度、不发送密码、无任务写入。若需要重新认证，将停止并明确记录，不能当作静默成功。

仍未覆盖：真实认证自然到期、物理网络中断、产品离线队列／升级恢复、复杂原生字段／重复任务／子任务的实测保护、分页／同步游标失效、最终组件打包，以及实际工时写入后完成原提醒事项的集成闭环。

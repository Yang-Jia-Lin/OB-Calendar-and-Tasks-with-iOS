# 开发、验证与文档约定

更新：2026-11-08。当前为 Windows 0.1.3 与 OB 0.8.1 轻量连接。用户已完成原数据交接与安排日期验证；程序发布不自动重载或再次迁移。需求见[产品需求](1-产品需求.md)，技术边界见[架构设计](2-架构设计.md)。

## 1. 文档与目录

根 `README.md` 只作项目入口与状态说明。`Notes` 当前只保留本约定、产品需求、架构设计、使用与迁移、开发日志。旧方案、长篇版本历史和旧交接集中于 [Archive](Archive/2026-11-07-OB完整工作台/README.md)，只供回溯，不作为现行要求。

`Agents/AGENTS.md` 是 AI 工作入口，`Agents/Handoff.md` 只写当前状态、最新决定和下一步，不再叠加所有历史交接。历史阶段的失败、后续更正和验证限制保留在归档，不改写成从未发生。

源码、构建、测试与探针在 `Coding/`；产品产物与现有探针运行环境在 `Results/`。检查报告、编译测试和临时验证数据在 `Agents/Tests/`，截图在其 `Visuals/`；旧程序备份在 `Agents/Backups/`。依赖、凭据、Cookie、会话、精确对象 ID 和业务缓存不进入 Git。

第三方源码／许可证、源代码中的可执行 Markdown 模板不按“旧项目文档”搬动。探针 README 保留为 Windows 运维参考，不当作正式产品 API。旧已删除存档不重建。

## 2. 实现边界

目标为 Windows 完整桌面服务与界面、OB 轻量按钮连接、Mac 原生 App 加独立轻量计时。活动会话留在本机，结束工时写入 iCloud 日历，不引入跨设备进行中同步、全局锁或接管服务。

复用 `Shared／Providers／Clients` 分层及已有可靠性规则，Windows 同步核心从 OB 宿主迁出。Mac 可使用原生技术实现相同业务语义，不为了复用 TypeScript 强行带入整套 Windows／OB 运行环境。新增目录、框架和依赖在实际实施时建立，不为文档方案预建空工程。

当前 Node.js 24.14.0、Python 3.13、PowerShell 7 是既有 Windows 工程环境；不据此宣称 Mac 可运行。Mac 的 Xcode／系统版本、签名、沙盒和日历权限在真机原型阶段记录。

## 3. 验证与记录

每次实质开发、方案调整或验证后，在[开发日志](开发日志.md)最前增加日期、范围、变更、实际结果、产物和未完成项。使用北京时间；纯文档工作不虚增版本。

文档改动核对本地链接、当前目标一致性、归档完整性及改动范围，不因文字更新运行无关业务测试。核心逻辑运行适用的 TypeScript／核心测试；UI／DOM 改动运行对应浏览器回归；平台后台、认证和日历桥接必须另做相应平台检查。

区分模拟、隔离真实样例、完整宿主与用户原生 App 验收。未重新执行的历史成绩写明是历史结果。Mac 尚未运行的功能不写“已兼容”，本地系统日历保存不写“云端全确认”。真实验证使用明确的专用样例，不把用户业务对象当作可随意清理的测试数据。

## 4. 现有插件构建与发布

在 `Coding` 执行：`npm run check`、`npm test`；界面回归使用 `npm run test:ui`，需要时先构建并启动 `npm run preview`。`npm run build` 只构建；`npm run release` 构建并安装；`npm run release -- -NoInstall` 只输出发布文件。

插件产物固定在 `Results/Obsidian/V<manifest版本>_calendar-task-timer/`，仅 `main.js`、`manifest.json`、`styles.css`，不生成 ZIP。需要渠道时追加 `_preview`／`_stable`，ID 保持 `calendar-task-timer`。浏览器预览位于 `Results/Preview/Obsidian/`。当前及迁移桥接版放端目录，其他旧版进入该端 Archive；普通开发不整理账户和业务数据。

既有授权继续适用于真正的插件版本更新：检查通过后运行 `npm run release`，仅覆盖 `D:\笔记\.obsidian\plugins\calendar-task-timer` 三个程序文件；变化前备份，核对版本与 SHA-256。保留 `data.json`、sessions、Migration 和其他用户数据，不自动重载、不结束正在进行的计时。

该脚本只安装 OB 插件的三个程序文件，不安装桌面应用，不自动重新加载或切换连接模式。

Windows 桌面源码为 `Coding/Clients/Desktop`，`npm run desktop:build` 构建前端与后台；`npm run desktop:runtime` 准备固定运行时，`npm run desktop:package` 使用 Tauri／MSVC 生成用户级 NSIS 安装包。开发依赖、原生 target 和诊断输出在 `Agents/Tests/Desktop` 及 `Agents/Tests/toolchains`，不入 Git。安装包和对应说明／校验值放在 `Results/PC/V<版本>_calendar-task-timer-desktop_preview`，不自动安装桌面 App。

新增检查：`npm run test:desktop-ui` 使用隔离夹具验证交互；`npm run test:desktop-smoke` 验证实际随包 Node／Python、本地协议、持久化及延迟。原生测试启动器使用独立离线数据目录，CPU／内存按该宿主及其完整子进程树统计，不读取真实账户；模拟睡眠、原生宿主和真实休眠分开记录。当前构建实测环境为 Node 24.14.0、Python 3.13.5、Rust 1.99.1、MSVC 14.44／Windows SDK 26100；开发机需要相应构建工具，最终用户无需安装 Node 或 Python。

安装路径回归用 `npm run test:desktop-paths`，必须覆盖 Windows 扩展路径、中文及空格；Node 启动选项与原生宿主共享。随包后台测试默认使用扩展路径，并可通过 CTT_SMOKE_RESOURCES 指向只读的实际安装资源，所有业务仍使用独立离线目录；不能仅以开发目录 resources 覆盖启动成功判定安装后可用。

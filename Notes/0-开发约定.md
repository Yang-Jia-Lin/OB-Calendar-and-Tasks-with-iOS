## 开发日志更新约定

每次有实质开发、版本发布、需求／架构变更或验证结果时，都更新 `Notes/开发日志.md`。在“开发记录”之后插入最新条目，新日期／新版本置前；同日新事项置前，版本按数字倒序。说明变更、已执行检查、证据／产物／提交及未完成项，复用日志内模板。

旧条目保留当时的失败、后续更正和能力边界；未重跑的检查不能写成此次通过，未完成的集成不能用探针成绩代替。纯文档调整不虚增版本、不自动打包／安装／推送，也不触发真实账户操作。当前需求与架构保持在各自主文档，开发经过归日志。

`npm run build` 输出 `Results/Release/V<manifest版本>_calendar-task-timer/`，只保留 main.js、manifest.json、styles.css，不生成 ZIP。需要区分渠道时，`npm run release -- -Channel preview` 或 `-Channel stable` 在文件夹追加 `_preview`／`_stable`；渠道只标在产物目录，插件 ID 与版本仍取自 manifest。未区分渠道时保持原目录名。

浏览器交互预览放 `Results/Release/Preview/`，`npm run preview` 从此目录读取；不再使用外层 Results/Preview。交互预览不是可安装插件的 `_preview` 渠道，安装仍只取版本目录内的三个标准文件。

用户已授权今后插件更新后自动覆盖安装。相关检查通过后运行 `npm run release`：构建并核对三文件、插件 ID／版本与 JavaScript 语法，再复制到 `D:\笔记\.obsidian\plugins\calendar-task-timer/`，逐文件 SHA-256 核对。目标存在其他插件 ID 时停止；目标三文件有变化才备份到 Agents/Backups/Before-Install-*。仅覆盖这三份文件，保留 data.json、sessions、Migration 等全部用户数据，不自动禁用／重载正在运行的插件。实际加载新版本可在计时结束后重启 Obsidian 或重新启用插件，不因安装擅自结束会话。

`npm run build` 仍只构建；`npm run release -- -NoInstall` 只交付版本目录；换库用 `-VaultPath` 显式指定已有 Obsidian 库。纯文档工作不必触发安装。

Results 保留最新可安装目录和前一版回退目录。用户已删除旧存档，不重建。Agents 中的历史报告、编译测试、临时文件及旧备份允许清理，后续检查按需生成；使用普通继承权限，不设置管理员独占 ACL 或只读保护。账户会话、私有 ID 清单、待同步／恢复状态属于业务运行数据，清理辅助产物时不要混删。历史条目保留当时的路径与测试事实，当前位置／删除情况以最新日志为准。修改核心运行 check／test，修改 UI／DOM 后运行浏览器回归；仅修改发布／安装脚本时验证产物、语法、覆盖文件及用户数据保护，不重跑真实云端新建／删除。

提醒事项 `Setup.ps1` 按固定提交和 SHA-256 准备 SDK，锁定依赖。Results 内环境、上游源码、状态与 ACL 保护的 `.private` 不进 Git；整合不删除现有会话。运行与恢复工具见探针 README。

## Git 迁移与恢复

### 日常自动提交与推送

用户已授权：重大功能、新阶段接入、重要同步／数据可靠性修复或实质架构变更完成，且相关检查通过后，自动 commit 并正常 push 到已核对的现有远程。这里的“重大”按实际影响判断，不要求主版本号变化；仅文档调整、小幅 UI、命名／目录和产物清理不自动提交／推送。用户明确要求提交时执行，本轮已明确要求提交一次，包含此前文档整理与发布流程调整。每次实质开发仍更新日志。

提交前检查 diff，仅暂存本次相关内容，不吞并无关用户改动；确认当前分支、upstream 和远程地址，再推送。结果中记录 commit 与 push 是否成功。无 upstream 或远端已分叉时先核实，不用强推覆盖；网络／权限失败保留本地提交并报告。历史 force-with-lease 迁移不构成日常强推授权。

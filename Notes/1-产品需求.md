# 产品需求与实施顺序

基线：2026-11-01 用户最新确认。本文是需求主文档；架构见 [架构设计](2-架构设计.md)，已有成果见 [开发日志](开发日志.md)。目标产品与当前 0.3.2 插件分别描述，不能混作已完成能力。

## 1. 已确认的产品方向

| 决定 | 当前约束 |
| --- | --- |
| 电脑为记录主力 | 必须有独立桌面 APP，OB 未打开时仍可使用；它是目标产品，不再列为可选附属工具 |
| 桌面展示保持轻量 | 以待办和核心摘要为方向，不要求展示整月全部日程／记录；具体布局、范围和摘要内容待用户进一步考虑 |
| OB 为科研执行主阵地 | 在课题、任务和 Components 首页按钮中计时；插件主页面继续提供总览、记录编辑与异常处理 |
| 下一步先完善 OB／Components | 先统一科研任务关联和计时入口，再推进 iCloud 任务接入及桌面端；不先搭完整桌面界面 |
| 云端业务数据统一 iCloud | 日程／实际记录进入 iCloud 日历，行动任务进入真正的 iCloud 提醒事项，不新增任务云或自建同步服务器 |
| 日期语义分开 | 安排日期表示准备哪天处理，截止日期表示最迟何时完成；两者独立、均可为空 |
| 保留“待安排” | 无安排日期的任务集中收纳，不每天全部放进日期栏 |
| iPad 复用原生应用 | 继续补记、安排、查看和处理提醒事项，不开发替代原生日历／提醒事项的 iPad 客户端 |
| Android 暂缓 | 后续只读即可，不作为本轮或桌面首版的门槛 |

“全部 iCloud”指任务、日程和已保存记录的统一业务来源。OB 笔记正文仍由用户原有笔记管理方式保存；本地缓存、未同步草稿、恢复日志和凭据保护仍有必要，不引入第二份云端主库。未来桌面与 OB 需共享活动会话并支持接管；0.3.0 仅完成接口与设备身份边界，远端权威、接管互斥及离线冲突处理后续实现。

## 2. 四类业务内容

| 内容 | 典型动作 | 保存与显示 |
| --- | --- | --- |
| 生活补记 | 活动结束后，填标题／分类／起止时间并保存 | 直接写实际记录，不要求先建任务或启动计时 |
| 科研行动 | 从课题任务启动、暂停／继续、结束计时 | 一项任务可以对应多次工时；结束计时不默认等于任务完成 |
| 未来日程 | 安排会议、预约或具体工作时段 | 写日程；进入过去也不能自动认定已经实际执行 |
| 周期事务 | 例如每周六交周报，到对应周期日进入当天视图 | 维护重复规则与当前一轮状态；完成本轮不结束整个系列 |

课题、长期方向和可执行任务分开：课题保留研究背景与笔记；具体行动可计时；实际工时记录执行结果。科研分类用于选择写入日历，课题关联用于返回研究上下文，两者不是同一个字段。

计划与实际即使显示在同一天，也要可区分，避免把过去的未执行计划当实际工时，或把计划和对应实际记录重复计入摘要。是否保留计划对照及具体视觉形式尚未确定。

## 3. 任务日期与当天显示

- `scheduledDay`：准备执行的本地日历日期，不是时间点；不因时区变化自动平移到另一天。
- `due`：无截止、某日截止、某时刻截止三种语义；日期截止保留浮动日期，时刻截止保留 UTC 时间点和显示时区。
- 设置截止日期不自动填安排日期；安排到某天也不自动改截止日期。
- 某日任务栏按安排日期展示；截止提示另显示，不把仅有截止日期的任务偷偷当作已安排。是否增加“当日到期”分组由桌面设计再定。
- 无安排日期的任务进入“待安排”，即使有截止日期也不自动变成每天出现的任务。
- 如果用户给任务安排了具体时间，才另建未来日程并关联任务；实际计时仍单独记录。

显示日期不等于推送提醒，通知策略沿用原生能力，本轮不承诺另建通知系统。

例：周报可以周五安排处理、周六截止。论文阅读可以周二安排、无硬性截止。尚未决定何时处理的论文任务留在待安排，不复制进每天。

周期事务按其有效周期日在当天出现；下一轮何时可操作、漏做后保留／跳过／延期、是否提前显示，均尚未确认。不得默认删除未完成实例，也不把“漏做区域”建议当成用户已确认要求。

## 4. 各端职责与流程

### 电脑桌面 APP

承担日常全局入口：待办／待安排、核心摘要、快速生活补记和未来安排。任务可出现在对应日期的任务区域，日历事件与任务保持不同实体。历史仍可查询和补记，但不要求常驻界面展示整月历史。

常驻、置顶、桌面嵌入方式、默认日期范围、是否提供完整日历扩展页、摘要指标与具体界面都待定。不得把目前 OB 的 1:2 布局、完整月网格或新的统计模块直接搬成桌面需求。

### OB／Components

0.3.0 页签按 **计时／待办／日历** 排列，首次进入待办，之后恢复上次页签。从待办或 Components 开始计时保持当前页。三页共用任务、单一会话、日志及后台同步，页签显示轻量活动提示；切页保留各页筛选、草稿和滚动位置。只有小型导航栏吸顶，计时内容与任务／执行记录均自然滚动，不设独立列表滚动条。

- 计时页以当前会话、累计时长、暂停／继续及结束为主。用户加载后进一步要求纯沉浸计时：0.3.1 移除下方重要待办、置顶入口和数量设置。
- 待办页移除大计时卡，保留新增、分类、排序、编辑和行内计时。增加 Components 全部／已关联／未关联、未完成／已完成／全部、截止全部／今天／逾期／无截止／指定日期的组合筛选；本轮不增加安排日期。宽屏保留列表与执行记录 2:1 双列，窄屏待办在前、记录在后。
- 执行记录独立选日期，只显示该日已记录工时并按时间排序；任务未完成也保留其工时。按 0.3.2 最新反馈，不再混入已完成待办／完成事项卡片。完成元数据保留，但不投影到这里。
- 日历页使用 FCR 已有 `fc-calendar` 嵌入，默认月视图，沿用其交互、连接、设置及同步。首次进入创建一个实例，切页复用；FCR 替换与周期任务统一在下一阶段完成。

插件手动勾选与“结束并完成”走同一完成入口；稳定任务引用、UTC 完成时间和标题快照与勾选在同一次原子 Markdown 更新中保存。重复完成不重复记事件，取消完成保留历史，再次完成新增一次动作。“只记时间”不产生完成事件；旧任务和外部勾选没有准确时间时显示未知，不推断今天完成。

0.3.1 将三项筛选收进单个按钮弹层，顶部移除产品标题，页签直接置顶。待办编辑中增加独立删除操作及确认，保留已有工时／完成记录；正在计时的任务不能删除。课题绑定独立于待办行：Components 再次开始可重新打开已完成任务、按原稳定 ID 和快照重建已删除任务，不按标题找同名项，不重建其他任务或覆盖历史。关联待办仍可显示，选择“未关联”筛选可隐藏。未完成新绑定选择行为不变。

待办列表选中具体分类后，新建待办默认预填该分类；切回“全部”使用插件设置中的默认分类。仍可手动调整新增栏分类，普通刷新不覆盖手动选择，成功添加后恢复当前筛选分类／全局默认供下一项使用；切换筛选保留未提交的标题和日期。当前计时任务在列表中高亮并显示“计时中／已暂停”及累计时间，右侧按钮切为暂停／继续，同步主计时、命令和 Components 的同一会话；结束后恢复开始按钮，默认不完成任务。

课题卡片中的开始按钮引用同一项行动任务；仅增强用户已有的 Components 原生按钮属性：点击开始、按钮显示状态／时长、再次点击结束只记时间；不在 Markdown 中嵌入控件，不改卡片封面。点击后留在原科研页面，暂停／继续及明确完成仍可在插件页／命令操作。插件页、命令、状态栏和 Components 共同操作插件内同一会话和队列，不各建任务／计时器。

结束默认可以只记工时；用户明确选择“结束并完成”时才完成该任务或本轮事务。沿用用户已创建的原生按钮属性。根据 2026-11-01 反馈，按钮跟在标题后，右上角留给 Components 自带编辑／更多菜单；窄卡片换行，不能让菜单遮挡按钮。

### iPad 与手机

iPad 继续使用原生日历／提醒事项，对同一 iCloud 数据操作。生活补记希望电脑、iPad、手机都方便，但本轮优先电脑和现有 iPad 路径；Android 写入不承诺，后续先评估只读。

### 日记（2026-11-01 补充）

用户进一步要求创建日记时自动触发一次时间轴更新。0.2.19 通过既有 Daily Template 的 Templater 完成钩子调用同一更新接口，模板保存后只尝试一次，普通打开／编辑／保存不触发；失败保留正文并提示使用手动按钮。只增加触发入口，不自动创建日记，不改变用户自行调整的模板和生成区排版；不恢复已删除的日期／来源说明。触发适配与现有日记接口兼容，不依赖插件重载或新增常驻监听。

用户希望后续由插件自动生成日记，并能继续手动添加想法；当前已进一步授权先尝试手动生成当天时间轴，并明确同意保存为普通 Markdown。0.2.17 实现按钮／命令更新指定生成区，新日记模板改为时间轴＋个人补充，保留原有新记／修改查询；旧日记首次更新保留原汇总全文。排版模板可在 OB 直接修改，功能由插件独立日记模块维护。整篇日记自动创建、定时生成及更复杂汇总仍未实施。使用方式及修改位置见[日记时间轴使用](3-日记时间轴使用.md)。

Components 原生日历保留带星期的中文文件名，使用独立的 `日记日期` 日期属性，不依赖文件创建时间。日记模板同步生成该属性；“更新全部属性”仅对 Daily 目录下具有合法日期文件名的日记补齐缺失值，不覆盖已有日期、不向其他目录的文档添加该属性。普通编辑保存不自动重算日期。快照使用插件时间轴当前已加载数据，不把普通日程当作已执行工时，也不声称公开刷新接口已确认远端同步成功。

## 5. 实施顺序与验收

| 阶段 | 交付 | 完成标准 |
| --- | --- | --- |
| P0 本轮文档 | 统一需求、架构、验证边界 | 清除“桌面可选”“科研任务永久分库存储”等冲突表述；已有测试证据不丢失 |
| P1 已实现、待实机验收 | OB／Components 共用科研计时入口 | 一张实际课题卡片能启动已有任务；插件页可暂停／继续同一会话；结束只生成一份工时，不重复建待办，刷新后状态一致 |
| 0.3.0 三页基线 | 计时／待办／日历三页及应用边界 | 模拟回归及原生 FCR 嵌入通过；重载新版后的真实跨页操作单独验收，不自动重载 |
| 0.3.1 反馈改进 | 纯计时、紧凑筛选、待办删除与课题任务恢复 | 删除不等于完成，卡片从原稳定绑定恢复；已有工时和完成历史保留 |
| P2 iCloud 任务最小接入 | 普通提醒事项、任务绑定、日期与课题信息持久化 | OB 创建／编辑／完成同一提醒事项；iPad 可核对；不确定提交不重复创建；安排／截止独立往返，旧数据显式迁移；原生复杂字段受保护 |
| P3 必做桌面 APP | 独立运行的轻量任务／摘要入口、补记和安排 | OB 关闭仍能使用；从 iCloud 读取结果；不用在电脑与 iPad 重复录入；具体界面先确认再实现 |
| 周期能力验证与接入 | 当前一轮与下一轮、有效日期显示、完成语义 | 普通任务接口成功不能代替此项。若桌面首版承载周期事务，须先通过该项；未支持期间明确提示，不盲写系列 |
| 后续 | Android 只读等 | 不阻塞 P1—P3，不预建原生端工程 |

P1 可先复用现有 Markdown 任务与 FCR 写日历闭环，属于兼容过渡，不等于 iCloud 待办同步已完成。P2 后目标是提醒事项为唯一任务主记录，OB 表现为科研关联／视图，不长期维护两份独立可写任务。不得自动扫描整个笔记库并全量上传。

## 6. 已确定与待定的界线

已确定：桌面必做、电脑主力、OB 科研／计时、P1 优先、日期分开、待安排、iCloud 统一、iPad 原生、Android 后置。

当前实现：活动计时在发起设备恢复；本地日志／草稿确保断网不丢操作；任务与工时通过稳定身份关联。未来桌面将共享活动会话并支持接管，本轮尚不具备远端会话权威或全局计时锁。

待定：桌面布局与摘要、周期漏做政策、安排日期和课题关联在原生提醒事项中的可靠映射、旧 Markdown 的选择迁移方式。待定技术映射必须验证，不能假定 iCloud 提供任意自定义字段。

## 7. P1 原生按钮历史验收（0.2.16）

0.2.15 已实现原生按钮开始→显示时长→再点结束只记时间、与插件页暂停／继续同步。用户于 2026-11-01 明确反馈已验证、效果不错，同时指出右上角编辑／更多菜单遮挡按钮。该用户反馈是基础流程的实机验收，不扩展为独立核实的全部 iCloud 对账证据。

0.2.16 将按钮移到标题后，并为原生菜单留出空间；菜单悬停、长标题、计时中文字变长及窄卡片均已浏览器核对。只增强原有按钮，不添加 MD 代码块、不另建任务或计时器。141 项核心测试在 0.2.15 通过；本次仅布局调整，运行 TypeScript 和 99 项浏览器检查（77 原有＋22 原生按钮／菜单检查）。新版已覆盖安装，未自动重载运行中的插件，实机新布局待用户加载核对。

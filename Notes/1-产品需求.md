# 产品需求

更新：2026-11-07。本文是当前需求基线，取代“完整 OB 工作台优先、各端共享活动计时”的旧方向。实现方式见[架构设计](2-架构设计.md)，现有软件与切换说明见[使用与迁移](3-使用与迁移.md)。

## 1. 产品分工

| 端 | 要做什么 | 范围 |
| --- | --- | --- |
| Windows 桌面版 | 统一管理待办、日程、计时、工时与同步 | 可独立运行，后台计时和同步不依赖 OB 窗口 |
| OB／Components | 保留课题卡片按钮，显示状态和累计时长 | 通过轻量连接插件调用本机计时 App，不再长期维护完整待办／日历工作台 |
| Mac | 主要使用原生日历和提醒事项；另做轻量计时 App | 开始、暂停、继续、结束、本机恢复；结束后写入选定的 iCloud 日历 |
| iPhone／iPad | 继续用原生 App 查看和管理日程、提醒事项及已保存工时 | 本轮不另开发客户端 |

任务主记录使用 iCloud 提醒事项，日程和已结束工时使用 iCloud 日历。活动会话、待提交操作和恢复日志保存在各自电脑本机。OB 笔记正文继续由笔记库保存，不上传课题全文作为计时数据。

## 2. 计时语义

- 一台电脑同时只有一个活动计时；本机 OB 按钮、桌面窗口和菜单栏入口操作同一会话。
- 不同步 Windows 与 Mac 的开始／暂停／进行中状态，不提供跨设备接管或全局计时锁。两台电脑可以独立计时，已结束记录按各自稳定身份保存，不按重叠时间自动合并。
- 开始计时立即在本机持久化，成功确认后按钮才显示计时中。关闭 OB 或隐藏桌面窗口后仍可计时；完全退出计时程序需要有明确的保存／恢复语义。
- 暂停不计入工时。结束先保存真实起止、暂停区间／净时长和稳定记录 ID，再提交日历；断网不丢已结束记录。
- 默认结束只记工时。Windows 只有用户明确选择“结束并完成”时，才完成关联提醒事项或当前周期。Mac 首版只保存工时，任务完成在原生提醒事项操作。
- 按钮沿用现有课题上下文和稳定绑定，不按标题合并同名任务；重复点击／响应丢失不得产生第二份会话或工时。

## 3. Windows 桌面版

完整功能迁入独立桌面 App：待办查看与编辑、分类、当前计时、已结束记录、快速生活补记、日程安排以及登录／同步异常处理。已有日历与提醒事项能力迁移复用，保留冲突保护和恢复队列。

首版先完成可用功能，后续再统一视觉、布局和动画。主窗口以待安排任务池、日期安排区、当前计时及必要摘要为主，并提供记录与设置入口。待办首版支持手动排序、拖入日期安排、跨日期改期、拖回待安排和撤销；拖动不修改截止日期、不生成工时，按小时安排留到后续。

界面参考[日有回响](https://riyouhuixiang.com/#calendar)的任务池与日期安排思路，使用自己的简洁布局。首版包含桌面底层日历面板（月历＋选中日待办、日程和工时），支持移动、缩放、位置锁定及隐藏，不盖住普通应用窗口。首版灵动岛参考 [Fly Island](https://github.com/flyl1u/fly-island)的收起／展开形式，仅提供当前任务、时长、暂停／继续／结束和打开主窗口；全屏应用时隐藏。不增加任务量预测、每日投入建议、自动均摊或其他效率工具功能。

Windows 睡眠／休眠继续计时，手动暂停期间不计工时。关闭主窗口继续后台运行；明确退出保存为暂停。崩溃、断电和系统时钟异常与正常睡眠区分处理，按可靠边界恢复并提示核对。

安排日期表示“准备哪天做”，截止日期表示“最迟何时完成”，两者独立。无安排日期的任务保留在待安排中；只有截止日期也不自动每天排入计划。用户允许在提醒事项备注的应用信息区存放安排日期及必要关联，保留用户备注，先通过 Apple 原生编辑往返核对再用于真实任务。复杂／损坏／未知版本信息区停止写入。重复任务明确完成本轮后，新周期清除旧安排日期，不自动替下一轮安排。

普通日／周指定星期／月重复任务继续采用已确定的语义：漏做保留逾期，显式完成后进入下一个未来周期，不补造漏掉轮次；不存在的月日／夏令时时刻跳过。复杂规则、子任务和含子任务父任务继续保护，不自动降级。iPad 原生完成后更换实例身份的关联仍待验收。

## 4. OB 按钮

保留现有 Components 原生按钮，点击后留在课题页面；按钮展示本机计时状态与时长，再次点击结束并只记工时。暂停／继续可由本机计时 App 提供，连接层支持相应指令。

按钮发送稳定的任务／课题引用，收到本机服务确认后更新显示。计时 App 未运行时尝试唤起，未连接或操作失败时明确显示状态，不在 OB 内另启动一套独立计时。Windows 调用本机 Windows App；Mac 上的按钮调用本机 Mac App。

最终插件仅承担按钮、状态订阅和必要的笔记上下文适配，不保存 iCloud 登录凭据、不拥有云端同步队列。现有日记快照兼容要求单独验收；不以迁移为由删除日记、模板或已经生成的 Markdown。

## 5. Mac 轻量计时 App

日常待办、分类整理和日程编辑主要使用系统原生 App。计时工具只需轻量入口、任务／活动名称、工时日历选择、当前时长、开始／暂停／继续／结束，以及失败记录的补写入口；不复制 Windows 的完整待办管理界面。

活动计时完全在本机进行。开始和暂停不上传活动状态、不依赖 Windows，不需要为了计时保持网络连接。结束后先保存记录，再写入 Mac 已配置的 iCloud 账户下可写日历，由系统负责后续同步。用户已明确确认“结束后写入 iCloud 日历”。

本地日历保存成功和 iCloud 已上传要区分；离线、权限拒绝、目标日历不可写时保留工时，恢复后可重试且不重复创建。首版不要求读取整个提醒事项库，也不自动完成或修改提醒事项。Mac 没有进行中计时的云端镜像。

菜单栏小窗口作为建议形态，具体外观、最低系统版本和开发技术在 Mac 实施时核对。睡眠／唤醒、崩溃恢复和权限变化必须实机验证；异常恢复先展示已保存状态，再由用户确认继续或修正。

## 6. 现状与实施顺序

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| 当前已交付 | Windows 上的完整 OB 插件 0.6.1 | 保留已验证能力与已知限制；本次文档调整不宣称完成桌面迁移 |
| 1. Windows 后台与最小桌面入口 | 独立计时、本地日志、已有云端能力和受控导入 | OB 关闭后仍能计时；崩溃恢复／离线重试不丢失或重复工时 |
| 2. OB 轻量连接及交接 | 按钮调用本机后台，保存现有绑定 | 卡片与桌面同一会话；连接失败无假成功；旧插件停止作为第二个写入者 |
| 3. Windows 首版完整功能 | 主窗口、桌面日历、灵动岛、拖动安排、补记及异常处理 | 所有入口共用后台，保留日记手动／自动更新；先功能后视觉精修 |
| 4. Windows 迁移与发布 | 受控快照、原身份导入、唯一写入者交接及回退 | 原任务、绑定、历史、固定请求与未确认操作可追溯，原生和性能验收通过后切换 |
| 后续独立工作：Mac 最小计时工具 | 本机计时、结束写入系统 iCloud 日历 | 计时无网络依赖；权限、离线、睡眠和重复提交通过 Mac 实机检查 |

Windows 与 Mac 的实现次序可随实际设备验证调整。共同底线是先验证记录身份、持久化和结束后的日历互通，再迁移真实业务；不把跨设备活动计时作为前置任务。

Windows 已选 Tauri 2＋TypeScript 界面、独立 Node 核心、固定 Python 提醒事项适配器；本机连接使用受令牌保护的回环 HTTP 与状态推送。日记继续保留手动和自动更新。仍需实机验收桌面挂载、睡眠及原生备注往返；Mac 最低系统和权限范围在其实施时确认。Android 暂缓。
